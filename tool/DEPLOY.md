# Как вывести инструмент в интернет

Три способа, все бесплатные или почти. Сначала о том, что хранить в GitHub
можно, но не всё.

## Что можно класть в репозиторий, а что нельзя

Репозиторий `KumaNurmatov/ibpmvp` сейчас **публичный**: всё, что в нём лежит,
читает любой человек в интернете и индексируют поисковики.

Первичные документы класть туда нельзя. В одной только платёжке по заказу 666
есть расчётный счёт, БИК, ИНН и подпись директора; в CMR — ФИО водителя; в
договоре — банковские реквизиты обеих сторон и личная почта. Удаление файла
из репозитория не помогает: он остаётся в истории коммитов навсегда.

Варианты по возрастанию усилий:

1. **Сделать репозиторий приватным** — Settings → General → Danger Zone →
   Change visibility. Бесплатно, Actions остаются бесплатными в пределах
   2 000 минут в месяц, а разбор пачки занимает минуты. Самый простой выход.
2. **Разделить на два репозитория**: код остаётся публичным, документы и
   результаты уезжают в приватный. Дороже в настройке, зато код можно
   показывать.
3. **Документы вообще не хранить**: гонять через веб-приложение, забирать
   книгу и удалять пакет. Тогда репозиторий — только код.

Ниже предполагается, что репозиторий уже приватный.

## Способ 1. GitHub как база и как исполнитель (без хостинга, бесплатно)

Ничего разворачивать не нужно: исполнителем работает GitHub Actions,
хранилищем — сам репозиторий.

1. Settings → Secrets and variables → Actions → New repository secret:
   имя `ANTHROPIC_API_KEY`, значение — ваш ключ.
2. Создайте папку `inbox/` и перетащите туда файлы прямо на github.com
   (Add file → Upload files). Работает и с телефона.
3. Коммит запускает разбор. Через пару минут в `orders/` появятся
   `Заказы.xlsx` и `Заказы.json`, книга также висит артефактом у запуска.

Что это даёт: у реестра появляется история. Видно, когда и какая цифра
поменялась и каким документом это вызвано — то, чего в Google-таблице нет.

Чего не даёт: веб-страницы с кнопкой. Загрузка — через интерфейс GitHub.

Лимиты: публичные репозитории — безлимит, приватные — 2 000 минут Linux в
месяц на бесплатном плане ([GitHub Actions free tier](https://cicdcalculator.com/github-actions-free-tier)).

## Способ 2. Render (веб с адресом, бесплатно)

Бесплатный тариф запускает наш Docker-образ без переделок и даёт адрес вида
`https://ibp-zakazy.onrender.com` с сертификатом.

1. render.com → Dashboard → **New → Blueprint** → подключить этот репозиторий.
   Render найдёт `render.yaml` в корне и создаст сервис сам.
2. Он спросит значения `ANTHROPIC_API_KEY` и `IBP_ACCESS_TOKEN` — они помечены
   `sync: false`, то есть в репозиторий не попадают.
3. Первая сборка занимает несколько минут. Проверка: `/healthz` должен
   ответить `{"ok":true,"auth":true}`.

Что нужно знать про бесплатный тариф:

- **Сервис засыпает после 15 минут без запросов**, первый запрос после сна
  ждёт около минуты. Для разбора пачки документов раз в день это терпимо.
- 750 часов в месяц на аккаунт, 0.1 CPU и 512 МБ памяти.
- **Постоянного диска нет** — поэтому `IBP_DATA` указывает на `/tmp`. Пакеты и
  кэш распознавания исчезают при перезапуске, книгу забирайте сразу.
- Источники расходятся в том, требует ли Render карту при регистрации;
  проверьте на render.com/pricing перед тем, как закладываться
  ([обзор free tier](https://snapdeploy.dev/blog/free-cloud-deployment-platforms-2026-comparison)).

### Почему не Hugging Face Spaces

Раньше здесь был рекомендован HF. **Это больше не работает бесплатно:** при
создании Space видно, что Gradio и Docker требуют платного плана PRO, бесплатны
только Static Spaces — то есть статика без серверного кода. Наш инструмент —
сервер на Python, под Static он не попадает.

Остаётся вариант на будущее: переписать конвейер так, чтобы он целиком работал
в браузере (pdf.js для страниц, вызов API прямо из браузера с заголовком
`anthropic-dangerous-direct-browser-access`, сборка xlsx на клиенте). Тогда
подойдёт и бесплатный Static Space, и GitHub Pages, и ключ будет вводить сам
пользователь. Но это переписывание проверенной логики на JavaScript, а ключ
окажется в браузере — годится для «каждый со своим ключом», не для общего
сервиса.

Файлы `tool/deploy/space/` оставлены на случай, если появится платный план.

1. huggingface.co → New Space → SDK **Docker**, шаблон Blank, видимость
   Private. Имя, например, `ibp`.
2. Выложить код одной командой:

   ```bash
   tool/deploy/space/push.sh <ваш-логин> ibp
   ```

   Скрипт собирает во временной папке ровно то, что нужно образу (README с
   frontmatter, Dockerfile, `tool/` без тестов и данных) и пушит в Space.
   При запросе пароля вводите **access token** с правом write со страницы
   huggingface.co/settings/tokens, а не пароль от аккаунта.
3. Settings → Variables and secrets → **Secrets**: `ANTHROPIC_API_KEY` и
   `IBP_ACCESS_TOKEN` (пароль на вход). После сохранения Space пересоберётся.
4. Адрес появится вида `https://<логин>-ibp.hf.space`. Проверить, что живо:
   `curl https://<логин>-ibp.hf.space/healthz` → `{"ok":true,"auth":true}`.

Важно про диск: на бесплатном тарифе `/data` **не переживает перезапуск**.
Пакеты и кэш распознавания исчезнут, когда Space заснёт. Для разбора это
терпимо — книгу вы скачиваете сразу, — но постоянным хранилищем Space не
является. Постоянный диск от 20 ГБ стоит около 5 $/мес.

## Способ 3. Свой сервер с доменом (от 300 ₽/мес)

Когда понадобится постоянный адрес и память между запусками.

```bash
# на сервере
git clone <репозиторий> && cd ibpmvp
printf 'ANTHROPIC_API_KEY=sk-ant-...\nIBP_ACCESS_TOKEN=<пароль>\nDOMAIN=zakazy.ваш-домен.ru\n' > .env
docker compose -f tool/deploy/compose.yml up -d
```

DNS: одна запись `A` с именем `zakazy` на IP сервера. Caddy сам получит
сертификат Let's Encrypt, когда домен начнёт резолвиться.

---

## Что обязательно при любом публичном адресе

- **`IBP_ACCESS_TOKEN` задан.** Без него страницу открывает любой желающий и
  тратит ваш ключ к API. Приложение пишет об этом в лог при старте.
- **Ключ только в секретах хостинга**, не в коде и не в репозитории.
- Проверить, что живо: `GET /healthz` отвечает `{"ok": true, "auth": true}`.
  `auth: false` означает, что пароль не задан.

---

## Что проверено, а что нет

Проверено здесь: приложение поднимается и отдаёт страницу (`uvicorn`,
`/healthz` → `{"ok":true,"auth":false}` без пароля и `true` с ним), сборка
выкладки для Space даёт 160 КБ правильных файлов, при недоступном `IBP_DATA`
приложение не падает, а уходит во временную папку с предупреждением в логе.

Не проверено: **сборка образа Docker** — в среде, где писался код, не было
запущенного демона. Если `docker build` споткнётся, почти наверняка дело в
имени пакета poppler или в версии базового образа; ошибка будет видна сразу
на первом шаге сборки.
