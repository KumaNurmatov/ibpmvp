# Разбор первичных документов по заказам

Инструмент для учёта швейного производства: кидаете пачку первички —
договоры, спецификации, накладные, CMR, платёжки, банковскую выписку, сводный
реестр, фото и скриншоты. Он определяет, что есть что, разносит по заказам,
считает остатки и выдаёт книгу Excel той же раскладки, что ведётся вручную,
плюс лист со всем, что требует человека.

## Зачем

Сейчас цифры из PDF переносятся в таблицу руками: 59 заказов × 22 поля — это
больше тысячи чисел, перебитых глазами. Что это уже стоило на реальных данных:

| | |
|---|---|
| 88 320 ₽ | заказ 662: сумма отправки посчитана от другого количества |
| 215 049 ₽ | заказы 765 и 632 с долгом пропали из новой книги без следа |
| 129 000 ₽ | неустойка по заказу 666 не удержана: никто не сверил дату предоплаты с датой отгрузки |

Плюс водитель, записанный не в ту строку, изделие под чужим названием и пять
ячеек с `#VALUE!`. Инструмент убирает ручной перенос и сам сверяет арифметику.

## Две версии

**[`web/`](web/) — браузерная, основная.** Сервера нет: pdf.js читает
документы, запрос к модели уходит прямо из браузера, ExcelJS собирает книгу.
Хостится на GitHub Pages бесплатно. Документы не покидают устройство, ключ к
API каждый хранит у себя.

**[`tool/`](tool/) — серверная.** Тот же конвейер на Python: веб-приложение,
командная строка и разбор через GitHub Actions. Умеет DOCX и работает с одним
ключом на всех, но требует хостинга — см. [`tool/DEPLOY.md`](tool/DEPLOY.md).

## Три правила, на которых всё держится

**Считает программа, а не модель.** Модель приносит то, что написано в бумаге.
Суммы, остатки, просрочки и неустойки выводятся кодом — воспроизводимо и под
тестами. В схеме извлечения нет полей «остаток» и «недоплата»: их нельзя
извлечь, их можно только посчитать.

**Противоречие не разрешается молча.** Если спецификация говорит одну цену, а
накладная другую, берётся более доверенный источник, но расхождение остаётся
видимым замечанием. В таких местах и прячутся деньги.

**У каждого числа есть происхождение.** В книге к ячейке приложено имя файла,
из которого взято значение, на странице источник подписан под каждым полем.

## Проверки

```bash
python3 -m pytest tool/tests -q                     # 50 проверок серверной версии
node --test "web/tests/*.test.js"                   # 19 тех же проверок в браузерной
python3 web/tests/browser_check.py <папка-с-pdf>    # сквозной прогон в Chromium
```

Расчёты живут в двух реализациях и разойтись могут молча, поэтому наборы
тестов намеренно повторяют друг друга на одних и тех же цифрах — разборе пяти
настоящих документов заказа Аи 13.04.26/4 (договор 666/1-1).

## Что не проверено

Точность распознавания на живой модели: в среде, где это писалось, не было
ключа к API. Схема, промпт и запрос написаны по документации, но замерить
качество на ваших сканах нужно первым же прогоном — сверьте результат с
`web/tests/fixtures.js`, там тот же разбор, переписанный с самих бумаг.
