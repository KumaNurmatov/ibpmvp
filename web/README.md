# Заказы: дашборд и разбор документов

Две части, одна логика расчётов.

- **Дашборд** (`index.html`, `orders.html`, `order.html`, `admin.html`) — учёт
  заказов: процесс, карточки, графики, фильтры. Данные заводятся руками.
- **Разбор документов** (`parse.html`) — чтение первички моделью. Сейчас на
  паузе, но работает.

Обе части считают одним и тем же кодом — `lib/ledger.js`, — поэтому остаток,
просрочка и неустойка в дашборде и в книге Excel не могут разойтись.

## Где лежат данные

Файлом `data/orders.json` в этом репозитории. Сейчас там 44 заказа: 43 из
реестра Excel и заказ 666, разобранный из первички.

Читают все: файл раздаётся вместе со страницей. Пишет только тот, у кого есть
токен GitHub — он хранится в его браузере, страница коммитит через API. Отсюда
и разделение прав: смотрящий не «лишён кнопок», он физически не может
записать. И у каждой правки остаётся история — видно, кто и когда поменял
цифру, чего в таблице не было.

### Чтобы получить право правки

1. GitHub → Settings → Developer settings → Personal access tokens →
   **Fine-grained tokens** → доступ к этому репозиторию, право
   **Contents: Read and write**.
2. Открыть `admin.html`, вставить токен, «Сохранить доступ».

После сохранения GitHub Pages пересобирает сайт — правка видна остальным
через пару минут.

| Страница | Что делает |

## Стадии процесса

Заказ всегда стоит на одной из пяти ступеней, и считается она из тех же цифр,
что и остаток, — разойтись они не могут.

| Ступень | Когда |
|---|---|
| Ждёт предоплаты | заказ оформлен, денег не было |
| В пошиве | предоплата внесена, отгрузки ещё нет |
| Нет постоплаты | отгружено, постоплата не приходила |
| К сверке | постоплата прошла, остаток не нулевой (сюда же переплата) |
| Закрыт | остаток сошёлся |

Два названия из пяти — это листы книги Excel («нет постоплат», «недоплата»).
Остальные три в таблице нигде не отмечались: их приходилось держать в голове.
Из воронки на дашборде ступень открывается списком своих заказов
(`orders.html?stage=shipped`).

Замечания по документам и хвост списка дел убраны за шторку: их десятки, и
первым экраном должны быть деньги, а не разбор бумаг. Счёт в заголовке
шторки показывает, сколько их там, — закрытая шторка ничего не прячет.

Список «Что делать» строится из тех же стадий: по строке на незакрытый заказ,
сверху срочное — просрочка отгрузки и отгрузки без постоплаты. Сумма в строке
— это деньги, которые за ней стоят: ожидаемая предоплата, непришедший остаток
или неустойка на сегодня.

## Новый заказ

Кнопка «+ Новый заказ» в шапке (видна в режиме правки) открывает пустую
карточку. Она устроена как лист: слева подпись строки, справа значение,
считаемые строки — серые и показывают, из чего получилась цифра. Строки оплат
и ссылок добавляются кнопкой, Enter переводит к следующей ячейке. Ключ
карточки подставится из номера договора, если его не заполнить.

Файлы не загружаются на сайт: в блоке «Учёт» ставится название и адрес —
ссылка на Google Drive, как в таблице.

## Перенос реестра

```bash
python3 tool/import_registry.py реестр.xlsx web/data/orders.json --dry-run
python3 tool/import_registry.py реестр.xlsx web/data/orders.json
```

Скрипт читает блоки по 15 строк с обоих листов книги и переносит то, что в
ней написано: номер, договор, изделие, заказано, цену, отправку, оплаты и
ссылки из блока «Учет». Считаемые ячейки (сумма заказа, оплачено, остаток) не
переносятся — их считает сайт, а расхождение с книгой скрипт показывает
отдельной строкой. Карточки с тем же ключом заменяются, остальные остаются.

Чего в реестре нет — того нет и в карточках: водителя, машины, сроков по
договору и процента неустойки. Срок не подставляется «обычный»: без него
просрочка просто не считается, иначе сайт заявлял бы претензию по
выдуманному условию.

## Формулы на виду

В карточке каждая величина показана вместе с тем, из чего получилась:
`324 800,00 ₽ − 150 000,00 ₽` под строкой «Остаток». Это замена формуле в
ячейке: в таблице её видно по клику, здесь — всегда.

## Графики

Две формы, обе выбраны по работе данных: отгрузки и оплаты — две величины
одной природы по месяцам, это сгруппированные столбцы; долг нарастающим
итогом — одна величина во времени, это линия. Двух осей на одном графике нет
нигде. Цвета проверены валидатором: оба проходят все шесть проверок на
поверхности карточки в светлой и тёмной теме.

Долг бывает отрицательным — если заплатили вперёд, — и шкала это умеет.

```bash
python3 web/tests/browser_check.py <папка-с-pdf>      # сквозной прогон разбора
```

Расчёты живут в двух реализациях — JavaScript для сайта и Python для CLI, —
и наборы тестов намеренно повторяют друг друга на одних цифрах: разбор пяти
настоящих документов заказа Аи 13.04.26/4.

## Чего пока нет

- Данные в репозитории публичны, как и сам репозиторий. Прежде чем заводить
  реальные суммы по всем контрагентам, стоит сделать репозиторий приватным —
  но тогда GitHub Pages потребует платного плана.
- Правка одновременно с двух устройств: GitHub откажет второму и попросит
  обновить страницу. Для одного-двух человек это не мешает.
- Распознавание сканов не проверялось на точности — см. `parse.html`.
